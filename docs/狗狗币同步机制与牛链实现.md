# 狗狗币同步机制与牛链实现

更新：2026-10-15。以下区分源码机制、本地实现和待验收事项。

## 狗狗币如何同步

Dogecoin Core 是完整节点钱包。节点发现、链数据验证和钱包私钥管理分别承担不同职责：

1. 使用种子和本地保存的节点地址寻找其他节点；已知节点保存在 peers.dat，可在以后启动时继续使用。
2. 与多个节点握手，核对网络信息，交换链头信息，通过区块定位信息请求缺少的区块头和区块数据。
3. 检验收到的区块及交易，而不是直接相信对方给出的余额。分叉选择还涉及累计工作量，不能只比较区块数量。
4. 保存已验证的数据，重启后从现有进度补齐。断网时能够查看本地数据，但不能据此断言已与全网同步。
5. 钱包保存密钥并识别属于自己的交易；联网不会把私钥发送给其他节点。换电脑需要恢复自己的密钥，不能复制朋友的钱包来同步余额。

- 区块请求和消息处理：https://github.com/dogecoin/dogecoin/blob/master/src/net_processing.cpp

## 牛链借鉴什么

牛链的 EVM 账户、交易和链状态不同于狗狗币的 UTXO 数据结构。使用 Core-Geth 原有的 P2P、数据库、完整同步、区块验证和累计工作量链选择机制；不移植 Dogecoin 的网络协议，也不连接 Dogecoin 节点。

本轮新增的钱包适配：
- 每个安装实例可以只运行自己的一个节点。
- 固定创世哈希、链 ID 和网络 ID；拒绝旧客户端替代牛链规则客户端。
- 静态 enode 接入列表，交给客户端持续维护连接；节点身份及数据库保存在本机数据目录。
- 区分没有连接、正在同步和已连接；eth_syncing=false 本身不构成全网最新证明。
- 开始挖矿前检查同步及连接，普通朋友节点没有任何连接时拒绝开始挖矿。
- RPC、矿工控制接口和认证接口保持本机访问；只有明确配置的 P2P 接口才可以面向其他电脑。
- 本地交易记录重新核对收据；原已入块交易在重组后不再存在时，显示待重新确认。

首轮采用静态引导节点，不宣称已经具备 Dogecoin 同等规模的 DNS 种子、地址传播和容错网络。公网引导节点尚未部署，跨电脑仍须实际验收。

## 备份与同步的边界

可携带备份包含两个本地账户的标准 V3 加密 keystore，使用 ethers 的 scrypt 与 AES-128-CTR 实现；密码不经命令行参数或日志传递。本机运行密钥仍由 Windows DPAPI 保护。

新安装恢复备份后重新连接同一条链并同步，地址保持一致，余额由链状态重新查询。备份不包含区块历史、完整交易列表或合约应用资料。网络标签是误操作检查，不是 keystore 标准 MAC 认证的网络证明。

当前已完成独立安装目录的恢复测试；尚不能将同一台电脑上的测试称为另一台实体电脑的验收。如果所有节点的链数据都丢失且没有其他副本，只有私钥备份不能重新生成历史交易。

## 跨电脑验收

先在两台电脑部署同一候选程序和创世配置，确认不同节点身份、相同创世哈希，完成初次同步、双向转账、断网补同步、关闭重启、节点替换、加密备份恢复。然后验证第二个独立引导节点，以及钱包提示与实际节点状态一致。

GitHub 提供源码和安装文件；区块与交易由在线节点交换，不由 GitHub 托管链运行。
