## 为什么需要 4 GiB 内存

`network/genesis.json` 使用 `"ethash": {}`，即 Core-Geth 默认参数。默认数据集大小在 `consensus/ethash/algorithm.go` 中定义为：

```go
datasetInitBytes   = 1 << 30   // 创世时 1 GiB
datasetGrowthBytes = 1 << 23   // 每 epoch 增长 8 MiB
```

第 0 个 epoch 的 DAG 就是 **1 GiB**，这是硬下限，无法调低。实测一台 2 GiB 的机器（Alibaba Cloud Linux 3，可用 1359 MiB）不足以承载该节点，加系统与既有业务后会持续换页甚至 OOM。4 GiB 是本项目实测可用的最低配置。

## 配置

包根目录下的 `network-config.json`：

```json
{
  "version": 1,
  "chainId": 26261017,
  "networkId": 26261017,
  "genesisHash": "0x9590d27e9e5977eb00bf1fd794d93fce0cac22dad04dc3f25fc072ab0c87e053",
  "peers": [],
  "allowPeerIPs": [],
  "listenAddress": "0.0.0.0",
  "advertiseIP": "49.235.133.254",
  "coordinator": true,
  "restrictPeerIPs": false
}
```

**`advertiseIP` 必须是这台服务器自己的公网 IP。** 填错时节点照样启动、端口照样监听，但 enode 会宣告一个别人连不上的地址，且没有任何报错提示。改完必须重启 `NiuWallet.exe`，该值只在启动时读取。

## 放行端口

需要两层都放行，缺一不可。

**第一层，Windows 防火墙：**

```powershell
New-NetFirewallRule -DisplayName "NIU P2P 30871" -Direction Inbound -Protocol TCP -LocalPort 30871 -Action Allow -Profile Any
```

**第二层，腾讯云安全组：**

云服务器 CVM → 实例 → 防火墙 → 添加规则

```
来源：    全部 IPv4 地址
协议端口：TCP 30871
策略：    允许
```

钱包的控制台（18790）与 RPC 只绑定 `127.0.0.1`，不需要也不应该对外开放。

## 启动与验证

双击 `NiuWallet.exe` 启动。首次启动会生成 1 GiB 的 Ethash 数据集，在 4 核机器上耗时较长，期间界面显示"正在读取…"属正常，不要关闭程序。

确认已对外监听：

```powershell
netstat -ano | findstr 30871
```

应出现 `0.0.0.0:30871` 和 `[::]:30871` 两行 `LISTENING`。若显示 `127.0.0.1`，说明 `network-config.json` 未生效。

## 取 enode

```powershell
(Invoke-RestMethod http://127.0.0.1:18790/api/state).enode
```

当前引导节点：

```
enode://7d58f869b280877f5e55ad94bc27ac23d075e51df098dd8e53304e92a7656c1c08939fefbcca4ff2b735204bffc4a8fd73ee0babec8701b58cc1302396511b3d@49.235.133.254:30871?discport=0
```

**这串 enode 就是发给朋友的连接信息。** 前 128 位十六进制是节点公钥身份，存放在 `runtime\persistent\` 内，重启不会改变；它必须在**这台服务器上**生成，本地临时节点的 enode 无效。

## 关于"未联网"显示

引导节点的 `peers` 为空，在任何节点接入之前，钱包概览页始终显示 `节点连接 0 · 未联网`。

这个文案指的是"有多少对等节点连着我"，**与互联网连通性无关**，也不代表故障。引导节点的角色就是等待接入，验收时应以端口监听和外部可达为准。

## 验收（全部通过才能对外发放）

| 步骤 | 预期结果 |
|---|---|
| 朋友启动钱包 | "概览"页节点连接显示已连接，不为"未联网" |
| 双方区块高度 | 一致并持续同步 |
| 服务器挖出一个区块 | 朋友节点能收到，高度增加 |
| 服务器向朋友地址转账 | 对方余额变化 |
| 双方重启钱包 | 状态与余额正确恢复 |

第 3、4 步必须在**两台真实独立电脑**上完成。在同一台机器上用两个数据目录测试无法替代——它暴露不了公网连通、端口占用和地址传播的问题。

## 运维注意

- **保持开机**。引导节点是网络的入口，关机后新加入的节点就找不到入口了。已连接的节点之间仍能通信，但新人无法接入。
- **不要重置 runtime**。`runtime\` 含链数据库和节点密钥，删除后 enode 身份改变，朋友手里的配置全部失效。
- **定期备份** `runtime\` 目录。
- **磁盘空间**。系统盘 40 GB，实测 C 盘可用仅 13.9 GB。链数据库随使用增长，需定期查看剩余空间。
- **带宽 3 Mbps**。当前链只有创世块，流量极小。多节点接入或链增长后会成为瓶颈，届时需升级带宽。
- **安全组清理**。该实例安全组中存在 `TCP 22`（Linux 登录）与 `TCP/UDP 3389` 对全部 IPv4 开放的规则。22 端口在 Windows 上无用，3389 暴露公网有暴力破解风险，建议删除或改为仅放行管理员固定 IP。
