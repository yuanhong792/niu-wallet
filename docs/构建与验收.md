# 构建与验收

当前提供源码和集成验证，不是正式发行安装包。没有部署公共引导节点，不应把不同实验网络的余额混用。

## 节点

`node/` 是 Core-Geth v1.12.23 起始提交 `96b2afc25c7023bb500d14e8ed69455339b1ca90` 加上本仓库 NIU 改动后的对应节点源码树。上游 tests 下三个测试子模块未打包，来源及固定提交保留在 .gitmodules 与上游提交中；不将缺失这些数据的测试跳过视为测试通过。

新增规则位于 `node/params/niu/`，奖励入口位于 `node/params/mutations/rewards.go`，叔块拒绝入口位于 `node/consensus/ethash/consensus.go` 和矿工路径。规则仅对集成链 ID 26261017 生效，不改变其他链的奖励。

Windows 需要 Go、支持 CGO 的 MinGW-w64 C/C++ 编译器。编译器应安装在实际的 ASCII 路径下；目录联接仍可能被编译器解析回中文路径，导致链接失败。本机成功使用 Go 1.26.9 和 WinLibs GCC 16.2.0 / MinGW-w64 UCRT 14。编译器版本不构成发布安全审查。

PowerShell 示例，按自己的编译器路径调整：

```powershell
$env:GOTOOLCHAIN='go1.26.9'
$env:CGO_ENABLED='1'
$env:CC='C:\mingw64\bin\gcc.exe'
$env:CXX='C:\mingw64\bin\g++.exe'
$env:PATH='C:\mingw64\bin;'+$env:PATH
Set-Location node
go test ./params/niu ./params/mutations
go test ./consensus/ethash -run 'TestNIU|TestDifficultyCalculators' -count=1
go build -o ../bin/niu-geth-candidate.exe ./cmd/geth
```

本分支移除了依赖 Go 私有 runtime 符号的 `/memsize/` 调试工具及注册调用，避免现代 Go 的链接失败；不提供这个内存扫描端点。没有绕过链接器检查。

上游完整 Ethash 测试在本机存在缓存数量用例失败，未修改上游代码也可复现；干净临时目录下仍可复现。因此不宣称全部上游测试通过。具体共识边界测试和真实挖矿验证应分别查看。

## 钱包

安装 Node.js 后在仓库根目录运行 `npm ci`。运行无挖矿模块验证：

```powershell
node --test scripts/network.test.mjs scripts/portable-vault.test.mjs scripts/restore-wallet.test.mjs
```

图形入口源文件为 `tools/launcher.cs`，用 Windows PowerShell 5.1 执行 `tools/compile-launcher.ps1`。运行布局要求同目录包含 `engine/node.exe`、`QRCoder.dll`、`assets/`、`scripts/`、依赖和与所选模式对应的节点程序；单独编译一个 EXE 不等于完整钱包包。

默认旧本机模式依赖原上游 `bin/geth.exe`，链 ID 26261015，不使用新发行规则。朋友网络模式把 `network/network-config.example.json` 复制为根目录 `network-config.json`，填入真实节点和接入策略。普通朋友实例需要至少一个已核实的 enode；不会用空列表默默创建孤立链。示例不是可直接连接的公网配置。

## 验收范围

`scripts/verify-network.mjs` 在同一台电脑上运行两个独立进程、数据目录、节点身份和钱包，验证真实 PoW、1000 NIU 基础奖励、区块同步、双向转账、多收款地址和完整备份。它不能替代两台实体电脑、路由器和公网环境的验收。

真实挖矿验证只能在明确启动的本机环境运行，不配置 GitHub Actions 或 Codespaces 挖矿任务。

正式发布仍须通过跨电脑互联、掉线与重组场景、难度长期模拟、钱包锁定与恢复体验、费用估算、软件签名和发布核验。
