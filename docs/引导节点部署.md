# 引导节点部署说明

更新：2026-10-16。适用于需要多台电脑共享同一条链的场景。

## 为什么需要引导节点

每个下载者本地运行的节点都是一条独立的账本。引导节点的作用只有一个：让新节点知道该连谁，从而进入同一条链。它不持有你的私钥，不替你签名，也不需要你的信任。

没有引导节点时，每个人挖到的 NIU 只存在于自己电脑上，互不相认。代码对此有明确保护：`scripts/network.mjs` 在既没有 `peers` 又没有 `coordinator` 时直接拒绝启动，提示"尚未配置引导节点，不能启动朋友网络"。

主流币同样依赖这个机制。Dogecoin Core 主网使用 `seed.multidoge.org` 与 `seed2.multidoge.org`，测试网使用 `testseed.jrn.me.uk`；Bitcoin Core 维护 9 个 DNS 种子与 6 个静态节点。这些都是实际运行的服务器，只是由项目方而非使用者运营。

## 两种部署方式

### 方式一：自有公网 IP（家用宽带）

成本为零，适合长期个人使用。

1. 确认你有公网 IPv4。拨号（PPPoE）上网通常自带；通过光猫/路由器拨号则需要运营商分配公网地址。可在路由器后台或向运营商确认。
2. 在路由器做端口转发：外部端口 30871 → 内网这台电脑的 30871，协议 TCP。
3. 电脑防火墙放行 TCP 30871 入站。
4. 按下面的配置生成 `network-config.json`。

注意：家宽公网 IP 可能在断线重拨后变化。变化后需要更新配置并通知朋友重启。

### 方式二：云服务器

成本为服务器月费，但 IP 固定、可用性更可控。配置要求：

1. 操作系统与本机一致（Windows x64），因为钱包发行包内含 Windows 版节点程序。
2. 内存建议 4GB 及以上，磁盘预留 40GB 以上。节点数据库会随链高度增长。
3. 安全组放行 TCP 30871 入站，源 `0.0.0.0/0`。其余端口不需要开放；钱包的 RPC 与控制台只绑定本机回环地址，不对外。
4. 按下面的配置生成 `network-config.json`，把 `advertiseIP` 换成该服务器公网 IP。

**合规提示**：选择服务器所在地区与运营主体前，自行核实虚拟货币挖矿相关的适用要求。境内服务器的相关政策见 `testnet-kit/source/README.md` 引用的官方文件。本文档不作法律结论，也不提供规避要求的安排。

已实际部署并验证的配置见 `docs/引导节点服务器部署.md`。

**内存要求**：本链使用 Ethash，创世 epoch 的 DAG 即为 1 GiB（见 `consensus/ethash/algorithm.go` 的 `datasetInitBytes`），这是硬下限。实测 2 GiB 机器不足以运行，**建议 4 GiB 及以上**。

## 协调节点配置

把下面内容保存为解压后**包根目录**下的 `network-config.json`：

```json
{
  "version": 1,
  "chainId": 26261017,
  "networkId": 26261017,
  "genesisHash": "0x9590d27e9e5977eb00bf1fd794d93fce0cac22dad04dc3f25fc072ab0c87e053",
  "peers": [],
  "allowPeerIPs": [],
  "listenAddress": "0.0.0.0",
  "advertiseIP": "你的公网IP",
  "coordinator": true,
  "restrictPeerIPs": false
}
```

字段含义：

| 字段 | 作用 |
|---|---|
| `chainId` / `networkId` | 必须与创世配置一致，改错会被拒绝启动 |
| `genesisHash` | 必须与本链创世块哈希一致 |
| `peers` | 协调节点留空，由别人来连它 |
| `listenAddress` | `0.0.0.0` 表示对外接受 P2P 连接 |
| `advertiseIP` | 你的公网 IP，节点用它对外宣告自己 |
| `coordinator` | `true` 表示我是被连接的入口 |
| `restrictPeerIPs` | `false` 才允许任意来源接入 |

放好这个文件后启动钱包，本机模式会自动切换为单节点网络模式。

## 取协调节点的 enode

启动后，在钱包"备份与设置"页可以看到节点地址。也可以直接查询本机状态接口：

```powershell
(Invoke-RestMethod http://127.0.0.1:18790/api/state).enode
```

得到形如 `enode://<128位十六进制>@你的公网IP:30871` 的字符串。这是别人连接你所需的唯一信息。

如果该命令返回空值，说明节点还没起来，先看 `runtime/persistent/node1.log` 里的报错。备份读法：

```powershell
Select-String -Path ".\runtime\persistent\node1.log" -Pattern 'self="enode://' | Select-Object -Last 1
```

注意：这里的 `127.0.0.1:18790` 是钱包本地控制端口，只监听回环地址，不对外开放。`enode` 里的 30871 才是对外的 P2P 端口。

## 朋友使用的配置

把你的 enode 填入下面模板，作为 `network-config.json` 交给他们：

```json
{
  "version": 1,
  "chainId": 26261017,
  "networkId": 26261017,
  "genesisHash": "0x9590d27e9e5977eb00bf1fd794d93fce0cac22dad04dc3f25fc072ab0c87e053",
  "peers": ["enode://<你的128位nodekey>@你的公网IP:30871"],
  "allowPeerIPs": ["你的公网IP"],
  "listenAddress": "127.0.0.1",
  "advertiseIP": null,
  "coordinator": false,
  "restrictPeerIPs": true
}
```

差异点：朋友只需要连你，不需要被连，所以 `listenAddress` 用 `127.0.0.1`、`coordinator` 为 `false`，并把你 IP 加入 `allowPeerIPs`。

`peers` 最多可填 32 个。想提高冗余，可以把几位朋友的 enode 也互相收集后各自填上，这样任何一台在线其他人就能接入，不必依赖单一入口。

## 验收

配置完成后按顺序确认，任一步失败都不要继续发给别人：

1. 朋友启动后，"概览"页节点连接显示为已连接，`net_peerCount` 不为 0。
2. 双方区块高度一致并持续同步。
3. 在协调节点挖出一个区块，确认朋友节点能收到。
4. 从协调节点向朋友的一个地址转账，确认对方余额变化。
5. 重启双方钱包，确认状态与余额能正确恢复。

第 3、4 步必须在**两台真实独立的电脑**上完成。在同一台机器上用两个数据目录测试不能替代该验收，它无法暴露公网连通、端口占用和地址传播方面的问题。
