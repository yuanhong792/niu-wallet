# 创世 v2 升级与两台机器部署

更新：2026-10-16。本文是一次**创世参数变更**的完整记录与部署步骤。

## 为什么改

原来的创世难度 `0x20000`（131,072）是 2015 年以太坊主网的创世值。在只有家用 CPU 的网络上，这个起点意味着开局每个块只要不到 1 秒，链需要约 12,000 个块（约 78 小时）靠逐块调整把难度爬到平衡，期间多发行约 1,200 万 NIU（总发行量 20.9 亿的 0.57%）。

把创世难度直接设到平衡值，链从第 1 块起就是目标出块速度，没有这段过渡期。

## 改了什么

只改**创世数据**，没有改共识算法，因此**不需要重新编译节点程序**。

| 项目 | 旧值 | 新值 |
|---|---|---|
| 创世难度 `difficulty` | `0x20000`（131,072） | **`0x81b320`（8,500,000）** |
| 创世 `extraData` | `…7631`（"NIU integration rules v1"） | **`…7632`（"NIU integration rules v2"）** |
| 创世哈希 | `0x043bbafa5a26f243e33370e05f90521b771848fc6edda8bf451d900041153869` | **`0x9590d27e9e5977eb00bf1fd794d93fce0cac22dad04dc3f25fc072ab0c87e053`** |
| 链 ID / 网络 ID | 26261017 | 26261017（不变） |
| 节点程序 | sha256 `6ea95784172b2f2edb59c20ad8b263b7b1d33a88d820079e0cf0606c014e204b` | **同一个二进制，未变** |
| `params/niu/rules.go` | — | **未改**（算法本来就正确） |

`rules.go` 不改的理由，都有实测支撑：

- 难度平衡点由**桶宽**决定，与创世难度无关。桶宽 42 秒时，指数到达模型的平衡均值是 `42 / ln2 ≈ 60.6` 秒；蒙特卡洛实测 60.24 秒。改成 60 秒只会把平衡点推到 85.77 秒，反而偏离 60 秒目标。
- 难度地板 `minimum = 131072` 只是**下界**，它从不阻止难度上涨。实测链上难度从 131,072 一路涨到 184,138，就是这条规则在工作。
- 把地板抬到 1 亿会有害：它会让算力较小的机器**永远慢于** 60 秒。

## 一个容易忽略的安全检查

`scripts/lab.mjs` 启动时会比对**运行时创世**与**包内创世**，不一致就拒绝启动：

```
创世配置与当前程序不同，已停止，防止混用网络。
```

所以只换包、不清运行时，钱包会直接拒绝启动。这是设计如此，不要在部署时绕过它。

## 部署顺序

**必须两台一起换。** 创世哈希不同 = 两条不同的链，P2P 握手会因创世不匹配而拒绝，两台互相看不见。

建议顺序：**先服务器（入口），后本机**，然后才开矿。

### 每台机器都要保留的两个文件

| 文件 | 作用 | 丢了会怎样 |
|---|---|---|
| `runtime\persistent\wallet.dpapi` | 你的私钥（DPAPI 加密） | 地址改变，旧余额地址对不上 |
| `runtime\persistent\node1\geth\nodekey` | 节点身份 | **enode 改变，朋友手里的配置全部失效** |

服务器上的 `nodekey` 尤其不能丢。

### 每台机器都要删掉的东西

```
runtime\persistent\genesis.json          ← 旧创世，不删会被安全检查拦住
runtime\persistent\node1\geth\chaindata  ← 旧链数据库
runtime\persistent\node1\geth\lightchaindata
runtime\persistent\activity.json         ← 旧链的交易记录
```

### 服务器（腾讯云 CVM，RDP 上去操作）

```powershell
# 0. 先停掉钱包（托盘退出），确认没有残留进程
Get-Process NiuWallet,niu-geth-candidate -ErrorAction SilentlyContinue | Stop-Process -Force

$old = 'C:\NIU-Wallet-0.3.4-lock-win-x64'
$bak = 'C:\niu-runtime-backup-{0}' -f (Get-Date -Format yyyyMMdd-HHmmss)

# 1. 备份整个 runtime（含密钥与节点身份）
robocopy "$old\runtime" $bak /E /NFL /NDL /NJH /NJS /NP

# 2. 解压新包
Expand-Archive 'C:\NIU-Wallet-0.3.5-genesis2-owner-review-win-x64.zip' -DestinationPath 'C:\' -Force
$new = 'C:\NIU-Wallet-0.3.5-genesis2-owner-review-win-x64'

# 3. 把密钥与节点身份搬过去（这一步决定地址和 enode 不变）
New-Item -ItemType Directory -Force -Path "$new\runtime\persistent\node1\geth" | Out-Null
Copy-Item "$bak\persistent\wallet.dpapi"            "$new\runtime\persistent\wallet.dpapi"
Copy-Item "$bak\persistent\node1\geth\nodekey"      "$new\runtime\persistent\node1\geth\nodekey"
```

然后在 `$new\network-config.json` 写协调节点配置（`advertiseIP` 必须是这台服务器自己的公网 IP）：

```json
{
  "version": 1,
  "chainId": 26261017,
  "networkId": 26261017,
  "genesisHash": "0x9590d27e9e5977eb00bf1fd794d93fce0cac22dad04dc3f25fc072ab0c87e053",
  "peers": [],
  "allowPeerIPs": [],
  "listenAddress": "0.0.0.0",
  "advertiseIP": "49.235.133.254",
  "coordinator": true,
  "restrictPeerIPs": false
}
```

```powershell
# 4. 启动并核对
cd $new
.\NiuWallet.exe
# 端口必须监听在 0.0.0.0
netstat -ano | findstr 30871
# 取 enode，确认前 128 位与升级前一致
(Invoke-RestMethod http://127.0.0.1:18790/api/state).enode
```

**升级后 enode 必须与下面这串完全相同**（前半段的公钥来自 `nodekey`，搬过去了就不会变）：

```
enode://7d58f869b280877f5e55ad94bc27ac23d075e51df098dd8e53304e92a6756c1c08939fefbcca4ff2b735204bffc4a8fd73ee0babec8701b58cc1302396511b3d@49.235.133.254:30871
```

如果这一串变了，说明 `nodekey` 没搬对，先停下来恢复备份，不要继续。

### 本机

步骤同上，只是配置换成本机（朋友/对等节点）的那一份：`peers` 填服务器的 enode，`listenAddress` 用 `127.0.0.1`，`allowPeerIPs` 填服务器 IP。

### 验收

| 步骤 | 预期 |
|---|---|
| 两台都启动 | 概览页显示已连接，`net_peerCount` ≥ 1 |
| 本机开矿 | 第 1 块在 **约 60 秒**内出现（不是 1 秒） |
| 连续观察 3 块 | 每块 30–120 秒之间（PoW 是随机过程，波动正常） |
| 服务器高度 | 跟着本机上涨，两台一致 |
| 转账 | 对方余额变化 |
| 重启两台 | 高度与余额恢复，**不出现高度 0** |

### 回滚

把 `$bak`（服务器）或 `E:\牛币\wallet-release\repository\runtime\recovery-backup-*`（本机）整个盖回原包目录的 `runtime\`，再把旧包换回去即可。旧链的链数据库仍在备份里。

### 本次实测结果（2026-10-16 13:00–13:35）


| 检查项 | 结果 |
|---|---|
| Go 规则测试 `params/niu`、`params/mutations`、`consensus/ethash` | 全部通过 |
| JS 测试（network / portable-vault / restore-wallet / vault-lock） | 9/9 通过 |
| 新包启动后 `genesisHash` | `0x9590d27e…87e053` ✓ |
| 新包运行时创世难度 | `0x81b320` ✓ |
| 本机钱包地址 | `0xca466C47fc094D6eC406e419023aAe170b262254`，**与升级前相同** ✓ |
| 节点身份（nodekey） | SHA256 未变，enode 不变 ✓ |
| ZIP 内是否夹带密钥/链库 | 0 条 `runtime/`、`*.dpapi`、`nodekey` ✓ |

**出块间隔实测**：单机 2 线程（该机实测算力约 250,000 H/s）连续 7 分钟采到 13 个块，真实间隔 **32.3 秒/块**。

这比目标的 60 秒快约 1.9 倍，需要如实说明：8,500,000 这个创世值是按早先测到的约 140,000 H/s 推的，而机器空闲时实测算力更高。

**为什么仍然保留这个值**：难度每块涨 0.0488%，链会自己爬上去——从 8.1M 爬到该机平衡值约 15M 需要约 1,300 个块（约 12 小时），期间出块从 32 秒逐步拉长到 60 秒，额外发行约 70 万 NIU（总发行量的 0.033%）。

刻意选偏低的理由是不对称：**偏低只是快十几小时，偏高会让链先慢十几小时**。若创世值偏高 2 倍，难度需要先跌下来，而在 120 秒/块的节奏下每块只跌 0.0488%，要跌一半得 47 小时——那段体验更差。

## 已知风险

- **服务器的旧链会被丢弃。** 升级前那条链上本机钱包有 709,899 NIU，服务器钱包为 0。这些余额随旧创世一起作废，这是本次变更的既定代价。
- **两台必须一起换。** 只换一台会出现"能连上但高度不动"，那不是故障，是创世不匹配。
- **服务器只能用 RDP。** 该机 22 端口关闭，只有 3389 开放。
- **节点程序未变，安全扫描证据仍有效**（`docs/security-build-evidence.json` 的 sha256 与二进制一致）。本次没有重新编译，也就没有让原 41 条扫描结论失效。
- **`docs/` 下四份证据文件仍记录旧创世哈希**（`network-verification.json`、`owner-desktop-qa.json`、`security-build-evidence.json`、`首发预备包验收.json`）。它们是对**旧创世**那几次验证的历史记录，故意不改写，不要当成当前网络标识。
